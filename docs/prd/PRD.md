## 1. 背景与问题

我在多个终端标签/窗口里并行开着 omp 会话（每个 tab 一件事），并持续在会话里踩坑、提问、被报错卡住。现有工具能看**额度**（姊妹项目 headroom 看每模型余量），但没有工具回答我真正关心的三个问题：

1. **每个切出来的标签，现在到哪一步了？** 命题是什么、进度如何、是不是我该回去看它了。
2. **我这些天"不会的"沉淀下来了吗？** 借用学习法：预习是找出不会的，听课是解决不会的，作业是检验不会的，复习是死磕不会的，改错是消灭不会的——我需要一个工具把散落在会话里的"不会的"收拢成知识点，排出温习节奏。
3. **今天到底干了什么、接下来做什么？** 一份每日快报。

**本项目要做的**：一个**只读**的本地私人教师，从 `~/.omp/agent` 读会话数据，把它变成一个终端看板（可塞进 zellij/tmux 面板，与 headroom 同栈同美学），并在需要时借 `omp -p` 做自然语言总结。

## 2. 目标与非目标

**目标（v0）**
- G1 看板：枚举每个终端标签/会话，自动从会话标题推断**工作命题**，按状态分 待办/进行中/已完成 三列，显示进度、活跃度、最近活动时间、是否在用（有绑定标签）。
- G2 进度：会话声明了 todo 就用 todo 完成度；否则用消息量活跃度作为进度代理（明确标注，不谎报完成）。
- G3 学习闭环：从最近会话里**全自动**挖掘"不会的"（用户提问 / 报错线索），落成知识点卡片，走 预习→听课→作业→复习→改错 五阶段，复习阶段带间隔重复排期，产出"今日要看"。
- G4 快报：把当天进行/完成/等待中的工作 + 今日要复习的知识点，汇成结构化快报，可由 `omp -p` 叙述成一段话，可导出 Markdown。
- G5 只读、隐私优先：绝不改任何 omp 配置、不触发切换；唯一落盘是本地学习库缓存 `~/.cache/tutor/deck.json`。
- G6 中英双语、可交互 TUI（tab 切换、方向键选择），也提供一次性 CLI 输出。

**非目标（v0）**
- N1 自动改 omp 配置 / 切模型（headroom 的 v1 领域，不在此）。
- N2 手动编辑卡片（提升阶段/标记改错/改排期）——v0 阶段由启发式+模型判定，手动操作留 v1。
- N3 watch 常驻自动轮询——v0 手动 `r` 刷新，留 v1。
- N4 直连各厂接口——只经 omp，单一可信源。

## 3. 需求（Requirements）

| 编号 | 需求 | 优先级 |
|---|---|---|
| R1 | 读 `~/.omp/agent/terminal-sessions/*` 面包屑，绑定 标签→会话（可用 `TUTOR_OMP_DIR` 覆盖根目录） | 必须 |
| R2 | 解析会话 JSONL：标题槽 + `session` 头（id/cwd/title/timestamp）+ 条目，容错跳过坏行，绝不 panic | 必须 |
| R3 | 工作命题 = 会话标题，缺失回退首条 user prompt | 必须 |
| R4 | 三列状态分类为纯规则（无 LLM）：todo 全完成→已完成；有部分完成/近期活跃/在用→进行中；其余→待办 | 必须 |
| R5 | 进度：有 todo 用完成度百分比；无 todo 用消息量活跃度代理，标注 `~` | 必须 |
| R6 | 学习：启发式从 user 消息里按线索词（报错/为什么/怎么/error/panic…）挖候选，落成 Preview 卡片；按 topic 归一去重、累计出现次数 | 必须 |
| R7 | 学习：`omp -p` 挖掘可把候选蒸馏成 {topic,detail,stage}，稳健解析被散文/代码围栏包裹的 JSON 数组 | 必须 |
| R8 | 学习：复习间隔重复排期（1/3/7/14/30 天），Preview 恒到期、Correct 永不到期；"今日要看"= 到期集合 | 必须 |
| R9 | 快报：结构化"今日进行/今日完成/等待/待复习"，可由 `omp -p` 叙述，导出 Markdown | 必须 |
| R10 | 只读：运行期不写任何 `~/.omp`；仅写 `~/.cache/tutor/deck.json`（原子写） | 必须 |
| R11 | 交互 TUI：看板/学习/快报三页，方向键选择、`l` 中英切换、`m` 挖掘、`b` 快报、`r` 刷新、`q` 退出 | 必须 |
| R12 | omp 缺失/`omp -p` 失败 → 明确可操作错误进状态栏，结构化事实照常显示 | 必须 |

## 4. 验收场景（Acceptance Criteria）

- **AC1（看板采集）**：对真实 `~/.omp/agent`，`tutor board` 枚举出全部标签/会话，命题取自会话标题，分入 待办/进行中/已完成 三列。
- **AC2（在用标记）**：被终端面包屑绑定的会话显示"在用/LIVE"标记。
- **AC3（进度降级）**：无 todo 的会话不显示假的完成度，而是活跃度代理 + 消息数；有 todo 的会话显示真实完成度百分比与进度条。
- **AC4（学习挖掘·离线）**：不调 LLM 时，含"报错/为什么/panic"等线索的 user 消息被挖成 Preview 卡片，归一去重后 `tutor tui` 学习页可见；Preview 卡片恒在"今日要看"。
- **AC5（学习挖掘·LLM）**：`m` 触发 `omp -p`，把候选蒸馏为带 stage 的卡片并合并入库；被 ```json 围栏包裹的输出也能解析（单测覆盖）。
- **AC6（间隔重复）**：复习卡按 1/3/7/14/30 天排期，未到期不进"今日要看"，到期后进入；单测覆盖。
- **AC7（快报）**：`tutor briefing --no-llm` 产出结构化 Markdown（今日进行/完成/等待/待复习）；`tutor briefing` 追加一段 `omp -p` 叙述；`omp` 失败时仍打印结构化事实。
- **AC8（只读）**：整个运行期不写 `~/.omp`；仅出现 `~/.cache/tutor/deck.json`。
- **AC9（健壮）**：坏行/缺失文件跳过不崩；空数据显示可操作空态；坏参数非零退出但不 panic。
- **AC10（发布）**：`cargo build --release` 通过；README 安装/运行命令原样可跑；`cargo test` 全绿；`clippy -D warnings`、`fmt --check` 干净。

## 5. 度量

- 一次扫盘 + 建看板 + 渲染 < 1s（纯本地，无 LLM）。
- LLM 仅在 `m`/`b` 手动触发，渲染路径零网络、零阻塞。
- 依赖最小（serde/serde_json/anyhow/ratatui/crossterm），与 headroom 一致。
- 领域层零 IO、可脱网单测覆盖分类/排期/解析核心算法。
